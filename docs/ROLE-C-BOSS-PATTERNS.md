# 역할 C 보스 패턴 구현 설명

## 구조

`GamePanel`에 스테이지별 타이머 분기를 복사하지 않고 다음 공용 흐름을 사용한다.

```text
GamePanel.update()
  -> BossPatternController.tick()
       -> RisingBlockPattern (스테이지 2)
       -> AccelerationPattern (스테이지 4)
       -> RandomKeyPattern (스테이지 5)
  -> BossPatternTarget(GamePanel)
       |- 1인: ASinglePlayerBridge -> Board/GameEngine/GameSession
       `- 2인: GamePanel의 board1/board2 양쪽
```

- 스테이지 1은 명세에 별도 주기 공격이 없어 `NoBossPattern`을 사용한다.
- 스테이지 3 도안 매칭은 시간 주기 공격이 아니라 별도 승리 조건이므로 아직 이 컨트롤러에 넣지 않았다.
- 경고와 공격 시간은 `BossPatternController`에서 한 번만 계산한다.
- 모드별 차이는 `BossPatternTarget`의 실제 보드 조작에서만 처리한다.
- 일시정지 화면에서는 `GamePanel.update()`가 호출되지 않아 패턴 시간과 임시 효과 시간이 함께 정지한다.
- 보스 격파, 게임오버, 스테이지 전환 시 `resetTemporaryBossEffects()`로 가속과 임시 키를 복구한다.

## 구현된 명세

- F-10: 줄 수별 10/25/40/60 데미지, HP 0 하한, 2초 클리어 연출, 요청 스테이지 유지
- F-11: 20초 주기, 3초 경고, 구멍 하나인 방해 줄, 고정/활성 블록 동시 상승, 상승 불가 시 게임오버
- F-13: 30초 주기, 3초 경고, 5초간 3배 중력, 발동 후 처음 스폰되는 블록 10배 중력
- F-14: 20초 주기, 3초 경고, 10초간 임시 키, Fisher-Yates, 원본/직전 결과 중복 방지, 2인 독립 매핑
- 기존 F-04 연동: 스테이지 3 이상에서 2인 P1/P2 가방에도 각각 15% 확률로 펜토미노 1개 삽입

## 수동 테스트

### 1인

1. 스테이지 2에서 17초에 경고가 나오고 20초에 보드와 활성 블록이 함께 한 칸 올라가는지 확인한다.
2. 스테이지 4에서 27초 경고, 30초 공격, 5초간 3배 중력과 다음 블록 10배 속도를 확인한다.
3. 스테이지 5에서 17초 경고, 20초 공격 후 표시된 조작이 10초 뒤 원래 키로 복구되는지 확인한다.
4. 각 효과 도중 일시정지하고 시간이 진행되지 않는지 확인한다.
5. 효과 도중 보스를 격파하거나 게임오버가 되면 즉시 원래 속도와 키로 복구되는지 확인한다.

### 2인

1. 스테이지 2 공격이 P1/P2 양쪽 보드와 활성 블록을 같은 시점에 올리는지 확인한다.
2. 스테이지 4에서 P1/P2 모두 3배 가속되고 각자 다음 블록 하나가 10배가 되는지 확인한다.
3. 스테이지 5에서 P1/P2 키가 각자의 원래 키 집합 안에서 독립적으로 바뀌는지 확인한다.
